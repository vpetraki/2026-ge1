### Μέθοδος και παραδοτέα

Κάθε εργασία περιέχει ερωτήματα που αφορούν την αναζήτηση βιβλιογραφίας (άρθρα, links, βίντεο). Στόχος είναι να αναπτύξετε τις απαντήσεις σας ως μια κριτική σύνθεση, να επιλέξετε τα καταλληλότερα άρθρα, να συνθέσετε συλλογισμούς από αυτά και να παραθέσετε τη δική σας προοπτική. Σημαντική είναι η κριτική σύνθεση κατ' αντιδιαστολή της απλής παράθεσης εναλλακτικών λύσεων-προτάσεων από διαφορετικές πηγές, κάτι που σημαίνει στη βαθμολόγηση δίδεται έμφαση στην ποιότητα της σύνθεσης και όχι στην ποσότητα των βιβλιογραφικών αναφορών.

Ο τρόπος εργασίας είναι ίδιος για όλα τα θέματα προγραμματισμού. Αρχικά, γίνεται εγκατάσταση του εργαλείου ανάπτυξης ή/και κάποιας βιβλιοθήκης. Στη συνέχεια, γίνεται εκτέλεση κάποιου απλού παραδείγματος από αυτά που είναι διαθέσιμα είτε στο περιβάλλον ανάπτυξης, ή/και στην αντίστοιχη βιβλιοθήκη, ή σε κάποια υπηρεσία διαμοιρασμού κώδικα (π.χ., github, stackoverflow) ώστε να είναι σίγουρο ότι όλα δουλεύουν. Στις περισσότερες περιπτώσεις, το ζητούμενο είναι μια μικρή μετατροπή του κώδικα του παραδείγματος ώστε να εξυπηρετεί άλλο σκοπό. Φυσικά, θα πρέπει να δώσετε αναφορά στην πηγή και να τεκμηριώσετε μόνο τις δικές σας αλλαγές. Σε κάθε περίπτωση ενθαρρύνεται ισχυρά η χρήση μεγάλων γλωσσικών μοντέλων αρκεί να είναι διακριτή η συνεισφορά τους και ο ρόλος σας.

*Παραδοτέα:* Για κάθε ερώτημα που ζητάει οθόνες από εφαρμογές ή απαιτεί εκτέλεση κώδικα, η απάντηση θα πρέπει να περιλαμβάνει μία ή περισσότερες ενδεικτικές οθόνες (screenshots) στις οποίες θα φαίνεται τόσο το περιβάλλον ανάπτυξης με τον κώδικα καθώς και το αποτέλεσμα της εκτέλεσης. Η αναφορά στο github περιέχει τις ενδεικτικές οθόνες μόνον με σύνδεσμο, τις οποίες θα πρέπει να έχετε [αποθηκεύσει σε github issue](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files) ή σε εξωτερική υπηρεσία αποθήκευσης αρχείων (π.χ., imgur, dropbox) και να βεβαιωθείτε ότι δεν είναι πολύ μεγάλες (π.χ., 100KB για κάθε εικόνα-οθόνη είναι συνήθως αρκετά). Ο πηγαίος κώδικας θα πρέπει να βρίσκεται σε ξεχωριστά δημόσια αποθετήρια, τα οποία μπορούν να είναι φορκ-αντίγραφο από κάποιο παράδειγμα που βρήκατε. Βίντεο ή/και εκτελέσιμος κώδικας είναι προαιρετικά και στέλνονται μόνο με κάποιο link σε υπηρεσία διαμοιρασμού αρχείων και όχι μέσω του study.eap.gr, στο οποίο υπάρχουν στενοί περιορισμοί όσον αφορά το μέγεθος των αρχείων.

## Μέρος A – Βιογραφικό σε ομαδικό οργανισμό Github (Ομαδική), 50 μονάδες

Ο στόχος αυτού του μέρους είναι η εξοικείωση με ένα σύστημα συνεργατικής ανάπτυξης λογισμικού. Για αυτόν τον σκοπό, θα γίνει ανάρτηση των ατομικών βιογραφικών σας συνεργατικά στον ίδιο ιστότοπο, μέσω ενός κοινού αποθετηρίου οργανισμού με δικιά σας αυτό-διαχείρηση στο σύστημα Github, το οποίο είναι μια από τις δημοφιλείς πλατφόρμες συνεργατικού λογισμικού. Θα δημιουργήστε ένα αποθετήριο για την ιστοσελίδα του φετινού τμήματος ΣΔΥ60 με τα [βιογραφικά](https://epidrome.github.io/teaching/cv/) όλων των φοιτητών με χρήση github οργανισμού, web hosting (π.χ., netlify), webring, και συνεργασία με αποθετήρια και αιτήματα ενσωμάτωσης. Για τον σκοπό αυτό, θα πρέπει [να οργανώσετε μια ομάδα με ρόλους, όπως διαχειριστής, μέλη, κανόνες λειτουργίας](https://epidrome.github.io/teaching/team/). Ο ομαδικός οργανισμός, το αποθετήριο με τα βιογραφικά, καθώς και η τελική ιστοσελίδα, θα πρέπει να είναι δημόσια. Η επιλογή της αισθητικής και της τεχνολογίας των επιμέρους βιογραφικών και του κεντρικού είναι δικιά σας επιλογή. 

Για την βαθμολόγησης της απάντησης θα πρέπει να δώσετε τους συνδέσμους τόσο προς το προσωπικό σας αποθετήριο του πηγαίου κώδικα όσο και προς την τελική ιστοσελίδα του βιογραφικού σας καθώς και προς το αίτημα ενσωμάτωσης στον οργανισμό. Η βαθμολόγηση της εργασίας αυτής γίνεται με βαρύτητα στην διαδικασία για τον συντονισμό της ομάδας, π.χ., δημόσιες-διαφανείς  οδηγίες και σχολιασμός (αντί για διαπροσωπική προφορική επικοινωνία) για την αποστολή και ενσωμάτωση αιτημάτων προς τον οργανισμό. Μπορείτε να βρείτε μερικά παραδείγματα [οργάνωσης ομάδων και διαδικασίας συνεργασίας](https://github.com/sdy60-2022) σε [μάθημα προηγούμενης χρονιάς](https://github.com/sdy60-2022/webring) [2](https://github.com/sdy60-2023/webring), [3](https://github.com/sdy60-2024/webring), [4](https://github.com/sdy60-2025/Webring). 

Η άσκηση αυτή είναι αρκετά εύκολη στην ατομική εκτέλεση (απλή επεξεργασία κειμένου σε markdown) αλλά έχει μεγάλη βαθμολογική βαρύτητα, γιατί απαιτεί αρκετή προσπάθεια για τον συντονισμό με τα άλλα μέλη της ομάδας, καθώς και χρόνο εξοικείωσης με συστήματα λογισμικού (Github, git, γραμμή εντολών, Linux) που κάποιοι ίσως δεν γνωρίζουν. Για όσουν δεν έχουν ήδη ένα σύστημα linux προτείνεται η πρόχειρη και γρήγορη λύση του virtual box + ubuntu. Το θέμα αυτό είναι σχετικά εύκολο για όσους έχουν ήδη εμπειρία και πρόσβαση σε ένα σύστημα γραμμής εντολών και σε συστήματα διακομιστή ιστοσελίδας, ανέφικτο για όσους αφήσουν αυτές τις απλές δεξιότητες για την τελευταία εβδομάδα ή μέρα πριν την παράδοση της ΓΕ. Για αυτό το λόγο, το μέρος Α έχει **πάρα πολύ ισχυρή σύσταση για έγκαιρη ενασχόληση** και θα επαναληφθεί και σε όλες τις επόμενες ΓΕ, ώστε να καλλιεργηθούν σταδιακά οι αντίστοιχες δεξιότητες σε μεγαλύτερο βαθμό.

**Παραδοτέο Β – Αυτόματη παραγωγή βιογραφικού σε μορφή PDF**

Στο πλαίσιο του Παραδοτέου Β υλοποιήθηκε διαδικασία αυτόματης παραγωγής του προσωπικού βιογραφικού σημειώματος σε μορφή **PDF μεγέθους Α4**, με χρήση των εργαλείων **Pandoc και XeLaTeX**.

Ως κοινή πηγή δεδομένων χρησιμοποιείται το αρχείο '_data/cv.yml', το οποίο αξιοποιείται και για την παραγωγή της ιστοσελίδας του Παραδοτέου Α μέσω Jekyll.

Για τη μετατροπή αναπτύχθηκε το πρόγραμμα 'build_cv.py' σε Python, το οποίο διαβάζει τα δεδομένα YAML, δημιουργεί ενδιάμεσο αρχείο Markdown ('cv.md') και εκτελεί το Pandoc με μηχανή XeLaTeX για την παραγωγή του τελικού αρχείου 'VasilikiPetraki.pdf'.

Η διαδικασία δοκιμάστηκε επιτυχώς τοπικά μέσω γραμμής εντολών των Windows.

Για την αυτοματοποίηση της διαδικασίας **( Continuous Integration / Continuous Deployment (CI/CD) )**  δημιουργήθηκε στο προσωπικό αποθετήριο GitHub το αρχείο .github/workflows/build.yml, το οποίο ενεργοποιείται αυτόματα με κάθε ενημέρωση του κλάδου main, ενώ παρέχεται και δυνατότητα χειροκίνητης εκτέλεσης μέσω του GitHub Actions. Το workflow αναλαμβάνει την εγκατάσταση των απαραίτητων εργαλείων (Python, PyYAML, Pandoc και XeLaTeX), την παραγωγή του PDF από τα δεδομένα YAML μέσω του build_cv.py και τη δημιουργία της ιστοσελίδας με Jekyll. Έπειτα, το παραγόμενο PDF ενσωματώνεται στην ιστοσελίδα και τα δύο δημοσιεύονται μέσω GitHub Pages. Η ορθή λειτουργία της διαδικασίας επιβεβαιώθηκε από την επιτυχή ολοκλήρωση των σταδίων build και deploy, καθώς και από τον έλεγχο της διαθεσιμότητας της ιστοσελίδας και του PDF.

Η μορφοποίηση του PDF προσαρμόστηκε ώστε να παρουσιάζει οπτική συνέπεια με την αντίστοιχη ιστοσελίδα του βιογραφικού.

### Σενάριο Χρήσης – Απομάκρυνση από περιοχή δασικής πυρκαγιάς

Ένα καλοκαιρινό απόγευμα, η Καλλιόπη βρίσκεται στο σπίτι της στη Νέα Πεντέλη μαζί με το παιδί της, όταν λαμβάνει στο κινητό της τηλέφωνο ειδοποίηση από την εφαρμογή για την εκδήλωση πυρκαγιάς σε κοντινή δασική έκταση. Ανησυχεί για την ασφάλεια της οικογένειάς της, καθώς η κατοικία της βρίσκεται κοντά στην περιοχή του περιστατικού. Επειδή έχει μετακομίσει πρόσφατα, δεν γνωρίζει καλά το τοπικό οδικό δίκτυο και τις εναλλακτικές διαδρομές απομάκρυνσης.

Πατώντας την ειδοποίηση, μεταφέρεται απευθείας στον διαδραστικό γεωγραφικό χάρτη της εφαρμογής, όπου εμφανίζονται η τρέχουσα θέση της, η τοποθεσία της πυρκαγιάς και οι περιοχές αυξημένης επικινδυνότητας.

Επιλέγοντας το εικονίδιο της πυρκαγιάς, βλέπει αναλυτικές πληροφορίες για το περιστατικό, τον χρόνο τελευταίας ενημέρωσης και την προέλευση των δεδομένων. Διαπιστώνει ότι η πυρκαγιά έχει επιβεβαιωθεί από τις αρμόδιες αρχές και ενημερώνεται για τις επίσημες οδηγίες πολιτικής προστασίας.

Λίγο αργότερα, λαμβάνει νέα ειδοποίηση από την εφαρμογή σχετικά με την έκδοση επίσημης οδηγίας απομάκρυνσης για την περιοχή της. Η Καλλιόπη επιλέγει τη λειτουργία «Οδηγίες Απομάκρυνσης», προκειμένου να πληροφορηθεί ποια διαδρομή μπορεί να ακολουθήσει σύμφωνα με τις οδηγίες των αρχών.

Η εφαρμογή εμφανίζει τη διαδρομή που αντιστοιχεί στις επίσημες οδηγίες, λαμβάνοντας υπόψη τα διαθέσιμα και επιβεβαιωμένα στοιχεία για την προσβασιμότητα των δρόμων. Η Καλλιόπη παρατηρεί στον χάρτη ότι ένας κοντινός δρόμος έχει αποκλειστεί και ότι η προτεινόμενη διαδρομή ακολουθεί διαφορετική κατεύθυνση από αυτή που θα επέλεγε αρχικά.

Ενεργοποιεί την πλοήγηση και λαμβάνει αναλυτικές οδηγίες ανά στροφή, τόσο οπτικά στον χάρτη όσο και μέσω φωνητικών μηνυμάτων. Με τον τρόπο αυτό δεν χρειάζεται να γνωρίζει τις ονομασίες των δρόμων ή να ερμηνεύει γενικές κατευθυντήριες οδηγίες.

Πριν ξεκινήσει, χρησιμοποιεί τη λειτουργία οικογενειακής ομάδας για να ενημερώσει τον σύζυγό της σχετικά με την κατάσταση και την προβλεπόμενη μετακίνησή της. Στη συνέχεια ακολουθεί τις επίσημες οδηγίες απομάκρυνσης, χρησιμοποιώντας την εφαρμογή ως βοηθητικό εργαλείο πλοήγησης.

Κατά τη μετακίνησή της, παρακολουθεί την πορεία της στον χάρτη και ενημερώνεται για τυχόν νέες επιβεβαιωμένες πληροφορίες που επηρεάζουν τη διαδρομή. Εάν δεν είναι πλέον δυνατή η αξιόπιστη καθοδήγηση, η εφαρμογή την ενημερώνει ότι δεν υπάρχει επιβεβαιωμένη διαθέσιμη διαδρομή και την παραπέμπει στις τελευταίες επίσημες οδηγίες.

**Αποτέλεσμα**

Η Καλλιόπη ενημερώνεται έγκαιρα για την κοντινή πυρκαγιά, αποκτά σαφή εικόνα της επικίνδυνης κατάστασης και κατανοεί ποιες πληροφορίες είναι αξιόπιστες. Όταν εκδίδεται επίσημη οδηγία απομάκρυνσης, μπορεί να ακολουθήσει αναλυτικές οδηγίες πλοήγησης, χωρίς να χρειάζεται να γνωρίζει το τοπικό οδικό δίκτυο.
